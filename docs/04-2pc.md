# 4단계. 2PC (Two-Phase Commit) 개념 정리

## 목표

2PC의 동작 방식과 한계를 이해하고, **왜 MSA에서 잘 쓰지 않는지** 설명할 수 있게 된다. 구현은 선택이다.

## 학습 내용

- [ ] 참여자(Participant)와 코디네이터(Coordinator)의 역할
- [ ] 1단계 Prepare(투표), 2단계 Commit / Rollback
- [ ] XA 트랜잭션과 MySQL의 `XA START`, `XA PREPARE`, `XA COMMIT`
- [ ] 코디네이터 장애 시 참여자가 **락을 잡은 채 대기**하는 문제 (블로킹)

## 선택 실습

- [ ] MySQL 두 개에 직접 XA 명령으로 2PC를 수행해 본다.
- [ ] `XA PREPARE` 후 커밋하지 않고 다른 세션에서 같은 행을 수정해 본다. 락 때문에 막히는 것을 확인한다.

## 정리할 질문

- 2PC는 어떤 일관성을 보장하고, 그 대가는 무엇인가?
- 코디네이터가 Prepare 후 Commit 전에 죽으면 어떻게 되는가?
- HTTP API로 통신하는 마이크로서비스, Kafka, Redis 같은 저장소가 섞이면 2PC가 왜 어려운가?
- 2PC와 TCC는 둘 다 "2단계"인데 무엇이 다른가?
